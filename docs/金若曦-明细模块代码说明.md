本文对应金若曦同学在个人记账本项目中负责的明细模块。阅读完这份文档后，应当能够独立说明模块的职责、代码执行顺序、前后端数据流、关键设计取舍，以及演示时可能遇到的问题。

### 阅读和运行前提

项目后端使用 Python 和 FastAPI，前端使用浏览器原生 ES Module。前端没有 npm 构建步骤，但页面需要由项目服务器提供，直接双击 `web/index.html` 可能受到浏览器模块加载和接口地址限制。

第一次运行时，在仓库根目录执行下面的命令。

```bash
pip install -r requirements.txt
uvicorn app:app --reload --port 8000
```

随后访问 `http://127.0.0.1:8000`，切换到“明细”页签。正常情况下会看到筛选栏、当前结果汇总和记录表格。

执行测试前也需要安装同一份依赖。若 `pytest -q` 在收集测试时报告 `ModuleNotFoundError: No module named 'fastapi'`，说明当前 Python 环境尚未安装项目依赖，不能据此判断业务代码失败。

## 二、职责边界

理解边界很重要。答辩时应准确说明自己写了什么，也应知道自己的代码依赖了哪些团队公共模块。

### 本模块直接负责的内容

- 生成明细页的筛选栏、汇总栏、表格和空状态
- 根据类型、类别、日期范围、备注关键词和显示数量查询记录
- 在浏览器中对当前查询结果排序
- 根据收入和支出类型联动类别选项
- 把当前筛选结果的收入与支出金额汇总出来
- 打开编辑弹窗并回填记录
- 收集编辑表单数据并发起更新请求
- 提供三秒有效的删除二次确认
- 处理加载、空数据、成功和失败等交互状态
- 处理弹窗焦点、键盘操作和辅助技术所需的语义
- 防止旧的异步请求覆盖较新的筛选结果
- 防止宽表格把移动端整页撑宽

## 三、模块在应用中的位置

`web/index.html` 为整个应用提供页面外壳。明细页预留了 `#records-view` 容器，并在页面脚本中导入本模块。

```js
import { mount as mountRecords } from "./js/records_view.js";

mountRecords(document.getElementById("records-view"));
```

挂载以后，本模块会生成明细卡片，绑定事件并读取首批记录。一次普通查询的完整路径如下。

```text
用户修改筛选条件
        ↓
records_view.js 更新 filters
        ↓
loadRecords() 组织查询参数
        ↓
api.js 发出 GET /api/records
        ↓
app.py 解析参数并调用 storage.query_records()
        ↓
SQLite 返回符合条件的记录
        ↓
FastAPI 返回 JSON
        ↓
records_view.js 保存 records 并调用 renderRows()
        ↓
浏览器更新汇总和表格
```

编辑和删除会多走一步。后端完成写入后，本模块调用 `refreshApp()`，让顶部指标、明细页和其他订阅者看到一致的新数据。

## 四、入口函数怎样启动模块

`mount(container)` 位于 `web/js/records_view.js` 末尾，是整个文件唯一导出的业务函数。它按下面的顺序完成初始化。

1. 把传入的 DOM 容器保存到 `host`
2. 调用 `ensureStyles()` 注入组件作用域样式
3. 修正主内容区域的最小宽度行为
4. 调用 `renderShell()` 生成明细页面骨架
5. 调用 `applyFilterInputs()` 把默认筛选状态写入控件
6. 调用 `bindEditModal()` 绑定编辑弹窗事件
7. 异步读取类别配置
8. 在明细容器上绑定筛选、输入和点击事件
9. 订阅全局的 `app:changed` 事件
10. 调用 `loadRecords()` 读取第一批记录

这段顺序有依赖关系。页面骨架必须先生成，后续代码才能通过 `querySelector()` 找到筛选控件。类别配置可以异步读取，记录列表不必等待它，因此页面能更早开始加载数据。

## 五、模块状态

这个模块没有使用 Vue、React 或其他状态框架。它通过文件顶部的模块级变量保存状态，再由函数主动同步 DOM。

### 默认筛选状态

```js
const DEFAULT_FILTERS = Object.freeze({
  type: "all",
  category: "all",
  start: "",
  end: "",
  keyword: "",
  limit: "20",
  sort: "date-desc",
});

const filters = { ...DEFAULT_FILTERS };
```

`DEFAULT_FILTERS` 是重置时使用的模板。`Object.freeze()` 防止代码意外修改模板。浅拷贝得到的 `filters` 负责保存变化。

这种写法让重置逻辑很简单。

```js
Object.assign(filters, DEFAULT_FILTERS);
```

### 其余模块状态

| 变量 | 保存的内容 | 存在理由 |
| --- | --- | --- |
| `config` | 收入和支出类别配置 | 筛选栏和编辑弹窗都要使用合法类别 |
| `records` | 最近一次有效查询得到的记录 | 渲染、排序、编辑查找都依赖它 |
| `host` | 明细模块的根 DOM 容器 | 限制查询范围并承载委托事件 |
| `keywordTimer` | 关键词防抖计时器 | 合并连续输入产生的查询 |
| `pendingDelete` | 正在等待第二次确认的删除按钮 | 保证同一时间只有一条记录处于确认状态 |
| `pendingDeleteTimer` | 删除确认过期计时器 | 三秒后自动恢复按钮 |
| `loadRequestId` | 最新列表请求的序号 | 丢弃已经过时的异步响应 |
| `modalReturnFocus` | 打开弹窗前获得焦点的元素 | 关闭弹窗后恢复键盘操作位置 |
| `bodyOverflowBeforeModal` | 弹窗打开前页面的滚动设置 | 关闭弹窗时准确恢复页面状态 |
| `unsubscribeChanged` | 取消全局订阅的函数 | 再次挂载时避免重复订阅 |

状态变量只服务于本文件。ES Module 自带文件级作用域，不会把这些名字挂到 `window` 上。

## 六、渲染策略

### 组件自己管理样式

`COMPONENT_STYLES` 保存明细模块的作用域样式。所有选择器都以 `#records-view` 开头，避免明细页的筛选栏、表格和按钮样式影响其他成员负责的页面。

`ensureStyles()` 在第一次挂载时创建 `<style>` 并放入页面 `<head>`。它通过固定的 `STYLE_ID` 判断样式是否已经存在，重复挂载不会重复插入。

筛选栏使用容器查询适应组件自身宽度。空间充足时七个控件保持一行，中等宽度时变成四列，小屏幕变成两列。布局判断依据是明细组件宽度，不依赖整个浏览器窗口宽度。

### 先生成稳定骨架

`renderShell()` 一次性写入筛选栏、汇总区域、表头、表体和空状态。之后筛选时只更新汇总和表体，筛选控件不会反复销毁。

这种分层让代码有两个清楚的渲染阶段。

| 阶段 | 函数 | 更新范围 |
| --- | --- | --- |
| 初始化 | `renderShell()` | 整个明细组件 |
| 数据变化 | `renderRows()` | 汇总、表体和空状态 |

### 用数据属性连接 HTML 和逻辑

控件通过 `data-filter` 标明对应的状态字段，操作按钮通过 `data-action` 标明行为。

```html
<select data-filter="type">...</select>
<input type="search" data-filter="keyword">
<button data-action="edit" data-id="...">编辑</button>
```

JavaScript 不需要为每个按钮设计不同的 `id`。它读取数据属性就能判断用户改了哪个筛选项，或者点击了哪条记录的哪个操作。

### 事件委托

表格行会随查询结果整体重建。如果给每一个编辑和删除按钮单独绑定监听器，每次重建后都要重新绑定。本模块把点击监听器绑定在稳定存在的 `host` 上，再通过 `event.target.closest()` 找到真正的操作按钮。

```js
const action = event.target.closest("[data-action]");
```

这就是事件委托。新增或重建的行会自动受到同一个监听器管理。

## 七、筛选功能

分工表写的是五类筛选。本模块实现的五类查询条件如下。

| 筛选类别 | 状态字段 | 后端参数 | 行为 |
| --- | --- | --- | --- |
| 收支类型 | `type` | `type` | 全部、支出、收入 |
| 收支类别 | `category` | `category` | 根据当前类型动态变化 |
| 日期范围 | `start` 和 `end` | `start` 和 `end` | 支持起始日期和结束日期 |
| 备注关键词 | `keyword` | `keyword` | 后端按备注关键词查询 |
| 显示数量 | `limit` | `limit` | 最近 20、50、100 笔或全部 |

页面还有排序控件。排序属于当前结果的展示方式，在浏览器本地完成，所以不计入后端筛选参数。

### 查询参数怎样生成

`loadRecords()` 从 `filters` 取出后端支持的字段。

```js
const params = {
  type: filters.type,
  category: filters.category,
  start: filters.start,
  end: filters.end,
  keyword: filters.keyword,
  limit: filters.limit === "all" ? undefined : filters.limit,
};
```

随后 `api.js` 中的 `buildQuery()` 会忽略空字符串、`all`、`null` 和 `undefined`。默认状态下不会生成没有意义的参数。例如类型为全部时，URL 中不会带上 `type=all`。

### 类型与类别联动

支出和收入拥有不同类别。`categoriesForType()` 根据类型返回对应数组。

| 当前类型 | 类别来源 |
| --- | --- |
| `expense` | `config.expense_categories` |
| `income` | `config.income_categories` |
| `all` | 两组类别去重后的并集 |

当用户改变类型时，`syncCategoryFilter()` 会重新生成类别选项。如果原来选中的类别不属于新的类型，它会把类别恢复为 `all`。

这个重置很关键。假设用户先选中支出类别“餐饮”，随后把类型改成收入。继续保留“餐饮”会形成一个语义冲突的组合，也很可能得到空结果。联动代码会主动消除这个无效组合。

类别文字来自后端配置，写入 `<option>` 前会经过 `escapeHtml()`。

### 日期范围校验

`validateDateRange()` 检查起始日期是否晚于结束日期。

HTML 日期控件产生固定的 `YYYY-MM-DD` 字符串。年、月、日都补齐位数以后，字符串字典顺序和真实日期顺序一致，因此这里可以直接比较。

```js
const invalid = Boolean(
  filters.start && filters.end && filters.start > filters.end
);
```

发现错误后，函数会完成几件事。

- 给两个日期输入框设置浏览器自定义有效性消息
- 设置 `aria-invalid` 供辅助技术读取
- 在用户刚修改日期时显示错误 Toast
- 阻止 `loadRecords()` 发出无效请求
- 让已经在路上的旧请求失效

后端 `app.py` 仍会再次检查日期格式和先后顺序。前端校验负责及时反馈，后端校验负责守住数据和接口边界。

### 关键词防抖

普通下拉框每次只产生一个明确选择，可以立刻查询。关键词输入会在短时间内产生很多 `input` 事件。直接请求会让输入“午饭”产生“午”“午饭”等多次查询。

本模块使用 300 毫秒防抖。

```js
if (keywordTimer) {
  window.clearTimeout(keywordTimer);
}
keywordTimer = window.setTimeout(() => loadRecords(), 300);
```

每次新输入都会取消上一个计时器。用户停止输入 300 毫秒后才会查询，既保留即时搜索感，也减少无效请求。

关键词写入状态时还会调用 `trim()`，避免首尾空格影响查询。

### 重置筛选

点击“重置筛选”后，代码会恢复默认状态、取消尚未触发的关键词计时器、同步所有控件、恢复类别列表、清除日期错误、退出删除确认状态，最后重新查询。

请求参数取自 `filters`，所以重置时需要同时恢复状态和 DOM 控件。

## 八、本地排序

后端接口没有排序参数。当前查询结果由 `sortedRecords()` 在浏览器中排序。

支持的顺序如下。

| 控件值 | 排序依据 | 方向 |
| --- | --- | --- |
| `date-desc` | 日期和创建时间 | 从近到远 |
| `date-asc` | 日期和创建时间 | 从远到近 |
| `amount-desc` | 金额 | 从高到低 |
| `amount-asc` | 金额 | 从低到高 |

金额先通过 `Number()` 转为数字，避免字符串排序出现 `100` 排在 `20` 前后的错误。

日期排序键由 `date` 和 `created_at` 拼接得到。同一天有多条记录时，创建时间可以继续决定顺序。

```js
const leftKey = `${left.date || ""} ${left.created_at || ""}`;
```

函数先用 `[...records]` 复制数组，再调用 `.sort()`。JavaScript 的 `.sort()` 会原地修改数组，复制后可以保留服务器响应的原始顺序，减少其他逻辑受到排序副作用的可能。

用户只改变排序时，代码直接调用 `renderRows()`，不会重新访问后端。

## 九、异步请求竞态保护

这是模块里最值得讲清楚的设计之一。

网络请求返回的先后顺序无法保证。假设用户先选“支出”，紧接着选“收入”，可能发生下面的时序。

```text
请求 1  查询支出  发出
请求 2  查询收入  发出
请求 2  先返回     页面显示收入
请求 1  后返回     旧结果试图覆盖页面
```

如果直接渲染每个响应，页面最后会显示支出，筛选控件却停留在收入，界面状态就不一致。

`loadRequestId` 为每次加载分配递增序号。

```js
const requestId = ++loadRequestId;
const data = await api.getRecords(params);
if (requestId !== loadRequestId) {
  return;
}
```

只有序号等于当前最新值的响应可以更新 `records`、显示错误或结束加载状态。早期请求依然可能在网络层完成，但结果会被忽略。

关键词继续输入或日期变为无效时，代码会主动递增 `loadRequestId`。这样无需等待下一次正式查询，就能立刻宣布已有请求过期。

这套方案处理的是响应采用权。它没有用 `AbortController` 取消网络传输，代码更简洁，代价是服务器仍会处理已经发出的旧请求。

## 十、表格和汇总渲染

`renderRows(data)` 同时负责汇总条、空状态和数据行。

### 当前结果汇总

函数遍历当前 `records`，分别累加收入和支出。

```js
records.forEach((record) => {
  if (record.type === "income") {
    income += Number(record.amount || 0);
  } else {
    expense += Number(record.amount || 0);
  }
});
```

这里显示的是当前筛选结果的金额。如果设置了显示最近 20 笔，汇总也基于返回的这 20 笔。顶部全局指标卡由 `refreshApp()` 管理，统计口径与明细汇总不同。

`data.count` 来自后端返回记录数量。只做本地排序时，函数用 `records.length` 作为数量，因为排序不会改变记录集合。

### 空状态

当 `records.length` 为零时，代码清空 `<tbody>` 并显示说明文字。用户会知道查询已经完成，只是没有匹配数据。

### 每行的表现

- 收入显示加号并使用收入颜色
- 支出显示减号并使用支出颜色
- 金额统一交给 `formatMoney()` 保留两位小数
- 空备注显示占位符
- 完整备注写入 `title`，截断时仍可悬停查看
- 编辑和删除按钮都保存当前记录的 `data-id`
- 两个操作按钮都带有包含日期、类别和金额的 `aria-label`

### 输出转义

记录内容最终进入模板字符串并写入 `innerHTML`。日期、类别、备注、记录编号和按钮说明在插入前都经过 `escapeHtml()`。

`escapeHtml()` 会处理下面五类特殊字符。

```text
&  <  >  "  '
```

例如备注中含有 `<script>` 时，它会作为普通文字显示，不能变成浏览器执行的标签。这是本模块主要的前端 XSS 防护。

记录类型由后端校验为 `expense` 或 `income`，再通过 `TYPE_LABELS` 映射成中文。

## 十一、编辑功能

编辑功能分成弹窗内容准备、打开、交互绑定、提交和关闭几个阶段。

### 弹窗 HTML 来自哪里

编辑弹窗位于 `web/index.html` 的 `#edit-modal`，包含记录编号、日期、类型、金额、类别和备注。`records_view.js` 不重复创建这段公共页面结构，它负责填值和控制行为。

### 打开弹窗

点击编辑按钮后，委托监听器从 `records` 中按编号找到对象，再调用 `openEditModal(record, action)`。

函数会完成下面的工作。

1. 确认弹窗存在且类别配置已经加载
2. 把记录字段写入编辑表单
3. 根据记录类型生成合法类别并保留当前类别
4. 记住触发编辑的按钮
5. 保存页面原来的滚动设置
6. 禁止背景页面滚动
7. 显示弹窗并更新 `aria-hidden`
8. 把焦点移到金额输入框

配置尚未加载时，模块会提示用户稍后再试，避免访问空配置导致脚本异常。

### 编辑类别联动

`populateEditCategories()` 根据编辑表单中的类型生成类别选项。原类别仍在新列表中时继续保留。原类别不合法时优先回退到“其他”，配置中没有“其他”时选择第一项。

因此，把一条支出改成收入时，表单不会继续提交支出类别。

### 弹窗关闭方式

用户可以通过以下方式关闭弹窗。

- 点击右上角关闭按钮
- 点击取消按钮
- 点击弹窗外的遮罩
- 按下 `Escape`

保存请求进行期间，`form.dataset.saving` 会被设为 `1`。此时 `closeEditModal()` 直接返回，避免用户在写入过程中关闭弹窗并误以为保存已经结束。

关闭后，页面滚动设置会恢复，键盘焦点也会回到刚才点击的编辑按钮。若刷新后该按钮已不在文档中，代码会跳过焦点恢复。

### 焦点约束

弹窗打开时，`Tab` 到达最后一个可操作元素后会回到第一个元素。`Shift + Tab` 从第一个元素继续向前时会回到最后一个元素。

这叫焦点陷阱。它防止键盘焦点跑到被弹窗遮住的页面内容中。

### 表单提交

提交事件先调用 `preventDefault()`，随后从表单收集数据。

```js
const payload = {
  date: form.querySelector('[name="date"]').value,
  type: typeSelect.value,
  amount: Number(form.querySelector('[name="amount"]').value),
  category: form.querySelector('[name="category"]').value,
  note: form.querySelector('[name="note"]').value.trim(),
};
```

金额在前端转为数字，备注清除首尾空格。前端检查日期非空，并检查金额是有限数字且大于零。

校验通过后，保存按钮会被禁用并显示“保存中...”。这能阻止连续点击产生重复更新。

请求路径为 `PUT /api/records/{id}`。后端会先读取原记录，只合并允许更新的五个字段，再运行完整校验并写入存储。

保存成功后的顺序如下。

```text
显示“记录已更新”
        ↓
解除弹窗保存锁
        ↓
关闭弹窗
        ↓
调用 refreshApp()
        ↓
刷新顶部指标并广播 app:changed
        ↓
本模块重新执行当前筛选查询
```

失败时弹窗保留，用户可以看到 Toast 后继续修改。`finally` 会恢复保存按钮，无论成功或失败都不会让按钮永久停在禁用状态。

## 十二、删除功能

删除会造成数据丢失，因此本模块没有在第一次点击时立即发送请求。它实现了一个小型状态机。

```text
普通状态
   │ 第一次点击删除
   ▼
等待确认状态
   │ 三秒无操作             │ 三秒内再次点击
   ▼                        ▼
普通状态                 删除中状态
                            │ 成功
                            ▼
                      全局刷新并重绘
```

### 第一次点击

`handleDelete()` 检查按钮的 `data-confirming`。值还不是 `1` 时，它会完成下面的变化。

- 清除其他记录可能存在的确认状态
- 把当前按钮文字改成“确认删除？”
- 更新按钮的辅助说明
- 增加确认样式
- 保存当前按钮到 `pendingDelete`
- 启动三秒计时器

同一时间只允许一个删除按钮等待确认。用户转而点击另一条记录时，上一条会恢复。

### 确认过期

三秒内没有第二次点击，计时器调用 `resetDeleteConfirm()`，恢复文字、样式和辅助说明，并清理计时器引用。

### 第二次点击

第二次点击先退出确认状态，再禁用按钮并显示“删除中...”。随后调用 `DELETE /api/records/{id}`。

成功后显示提示并执行 `refreshApp()`。失败后恢复按钮可用状态，保留当前表格，让用户可以重试。

后端在记录不存在时返回 404。`api.js` 会把后端错误整理成普通 `Error`，本模块只需统一显示 `error.message`。

## 十三、全局刷新机制

编辑和删除会影响顶部总收入、总支出、结余、记录数量，也可能影响统计和图表。只更新当前表格会让其他区域仍显示旧数据。

团队在 `api.js` 中提供了 `refreshApp()`。

```text
refreshApp()
   ↓
并行读取配置和全部记录
   ↓
更新全局 state.totals
   ↓
刷新顶部四张指标卡
   ↓
发出 app:changed
   ↓
各模块按自己的需要重新加载
```

本模块通过下面的代码订阅事件。

```js
unsubscribeChanged = on("app:changed", () => {
  loadRecords();
});
```

因此，其他模块新增记录、导入 CSV 或自然语言记账后，只要调用 `refreshApp()`，明细页也会保持同步。

再次挂载前会执行旧的 `unsubscribeChanged()`。这可以防止 `app:changed` 被同一个模块重复处理。

## 十四、加载和错误处理

### 加载状态

`setLoading(true)` 会给明细卡片设置 `aria-busy="true"`。请求结束后恢复为 `false`。辅助技术据此知道该区域正在更新。

模块没有用遮罩挡住整个表格。用户在请求期间仍能看到上一批数据，页面变化更平稳。

### 网络和接口错误

`api.js` 统一处理以下问题。

- 浏览器无法连接后端
- HTTP 状态码表示失败
- 后端返回多条校验错误
- 后端返回一般错误对象

它最终抛出带可读消息的 `Error`。本模块在 `catch` 中调用 `toast(error.message, "error")`。

旧请求即使失败也不会弹出错误。`catch` 会比较请求序号，只让当前最新请求报告问题。这可以避免用户已经改变条件后，又看到旧条件产生的错误。

### 写操作恢复

编辑失败会恢复保存按钮。删除失败会恢复删除按钮。两个流程都保留用户当前页面，便于检查或重试。

## 十六、响应式布局和独立滚动

明细表有六列，并设置了 `min-width: 760px`。小屏幕上由 `.table-wrap` 自己横向滚动。

CSS Grid 子项默认有内容最小宽度约束。宽表格可能把外层网格一起撑开，导致整个页面产生横向滚动。

挂载时的代码把主区域网格列设置为 `minmax(0, 1fr)`。

```js
const main = host.closest(".main");
if (main) {
  main.style.gridTemplateColumns = "minmax(0, 1fr)";
}
```

其中的 `0` 允许网格列收缩到内容最小宽度以下。表格的宽度压力就会留在 `.table-wrap` 内部，移动端整页不会被撑宽。

记录数量很多时，表格还会在组件内部纵向滚动。桌面端最大高度根据视口在 300 至 560 像素之间计算，手机端最多占视口高度的百分之五十二。记录继续增加时只会增加表格内部的可滚动内容，不会让明细卡片无限增长。

表头单元格使用 `position: sticky`。用户滚动到后面的记录时，日期、类型、类别、金额、备注和操作标题仍然停留在表格顶部。

`<colgroup>` 为六列声明稳定比例，配合 `table-layout: fixed` 防止内容长度改变列宽。筛选控件也设置了最大宽度，避免原生下拉框按最长选项撑出网格。

## 十七、安全边界

### 本模块已经处理的风险

- 动态记录字段在写入 HTML 前经过转义
- 更新只提交明确列出的字段
- 金额在前端检查为有限正数
- 日期范围在前后端分别校验
- 类别选项来自服务端配置
- 删除需要短时间内连续确认
- 保存和删除进行中会禁用对应按钮

### 最终可信边界在后端

浏览器代码可以被用户绕过，所以前端校验不能作为最终安全保证。`app.py` 会对更新后的完整记录再次执行 `validate_record()`。存储层负责真正的增删改查和快照同步。

当前项目定位为本地个人记账演示，没有用户登录、权限隔离和 CSRF 防护。若以后部署为多人公网服务，需要在后端增加认证、授权和更严格的跨域策略。这些工作不属于当前明细模块的职责。

## 十九、完整操作流程

### 筛选一次记录

1. 用户修改类型下拉框
2. `host` 上的 `change` 监听器取得 `data-filter="type"`
3. 新值写入 `filters.type`
4. `syncCategoryFilter()` 更新类别选项
5. `loadRecords()` 生成新的请求序号
6. `api.getRecords()` 发出查询
7. 最新响应写入 `records`
8. `renderRows()` 重新计算当前结果汇总并更新表格

### 编辑一条记录

1. 用户点击某行编辑按钮
2. 委托监听器通过 `data-id` 找到记录
3. `openEditModal()` 回填表单并管理焦点
4. 用户修改并提交
5. 前端整理 `payload` 并做基本校验
6. `api.updateRecord()` 发出 PUT 请求
7. 后端合并、校验并更新 SQLite
8. 成功后 `refreshApp()` 更新全局状态
9. `app:changed` 触发当前筛选重新查询

### 删除一条记录

1. 用户第一次点击删除
2. 按钮进入三秒确认状态
3. 用户第二次点击同一个按钮
4. 按钮被禁用并发出 DELETE 请求
5. 后端删除记录并同步存储
6. 成功后 `refreshApp()` 更新全局状态
7. 明细页重新查询，已删除记录从表格消失

## 二十一、常见追问

### 为什么筛选状态不直接从 DOM 读取

`filters` 是模块内部的统一状态源。请求、重置、类别联动和排序都读取同一个对象，避免不同函数各自解释 DOM。`applyFilterInputs()` 负责在需要时把状态写回页面。

### 为什么排序放在前端

当前接口契约没有排序参数，单次最多显示的常用档位为 20、50、100 条。本地排序响应快，也不需要扩大团队已经冻结的接口。选择“全部”且数据量很大时，服务端排序和分页会更合适。

### 为什么日期字符串可以直接比较

日期控件输出补齐位数的 `YYYY-MM-DD`。这个格式从高位年份排到低位日期，字典顺序与时间顺序相同。

### 为什么前端校验后还要后端校验

前端代码可以被修改，也可以绕过网页直接调用 API。前端校验提升交互速度，后端校验决定数据能否真正写入。

### 为什么需要 `loadRequestId`

多个请求可能乱序返回。序号让页面只采用最后一次查询的结果，从而让表格与当前筛选条件保持一致。

### 为什么删除确认不用浏览器 `confirm()`

行内确认不会阻塞整个页面，视觉风格也与应用一致。三秒自动恢复能避免按钮长期停留在危险状态。

### 为什么弹窗监听器只绑定一次

`bindEditModal()` 用 `modal.dataset.bound` 记录绑定状态。重复绑定会让一次提交触发多个请求，也会让键盘事件执行多次。

### `refreshApp()` 为什么还会让明细重新请求

写操作可能改变当前筛选结果和当前页汇总。全局刷新先更新顶部指标，再通过事件通知明细按自己保留的筛选条件重新读取数据。

### 当前汇总和顶部汇总为什么可能不同

明细汇总只计算当前筛选和数量限制下的 `records`。顶部指标表示全部数据的总计。两者回答的问题不同。

## 二十二、当前限制和后续改进

### 当前限制

- 列表采用数量限制，没有真正的页码和游标分页
- 本地排序只能覆盖本次已经返回的记录
- 旧请求会被忽略，但网络传输没有真正取消
- `refreshApp()` 读取一次全部记录，事件触发后明细又读取一次筛选记录
- 编辑表单的前端校验主要覆盖日期和金额，完整规则依赖后端
- 模块按页面只挂载一次设计，`host` 上的三个委托监听器没有单独的解绑入口
- 当前项目没有多人账户和权限控制

### 可以继续改进的方向

1. 用 `AbortController` 在新查询开始时取消旧查询
2. 给接口加入排序和分页参数，适应更大的数据量
3. 为编辑类别为空等异常配置增加显式保护
4. 把列表加载状态做成可见的骨架或进度提示
5. 为筛选、竞态、弹窗和删除状态机补充独立前端自动化测试
6. 让 URL 查询参数保存筛选条件，刷新页面后仍能恢复
7. 给组件增加 `unmount()`，完整清理计时器和 DOM 监听器

这些改进不影响当前作业验收。它们反映了数据规模、部署方式和组件生命周期扩大后需要处理的问题。

## 二十四、推荐阅读顺序

第一次自己读代码时，可以按下面的顺序进行。

1. 先读 `mount()`，建立初始化全貌
2. 再读 `DEFAULT_FILTERS` 和所有模块状态
3. 阅读 `renderShell()`，对照浏览器认识 DOM 结构
4. 阅读 `loadRecords()` 和 `renderRows()`，理解查询调用过程
5. 阅读 `mount()` 中的三个委托事件，理解交互入口
6. 阅读 `openEditModal()`、`bindEditModal()` 和 `closeEditModal()`
7. 阅读 `handleDelete()` 和 `resetDeleteConfirm()`
8. 最后打开 `api.js` 和 `app.py`，顺着请求继续追到后端

每读完一个函数，都可以回答三个问题。

- 它读取了哪些状态
- 它修改了哪些状态或 DOM
- 它可能发出哪些异步请求或事件

能够沿着一次筛选、一次编辑和一次删除完整讲完调用链，就已经真正掌握了这个模块。
